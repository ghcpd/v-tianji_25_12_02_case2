## 4) Breaking-change assessment — what will break and where it touches the code 🧭

Major upgrade candidates and expected breakage (and files affected):

1) React 16.x -> 19.x
   - Breaking concerns:
     - ReactDOM.render -> ReactDOM.createRoot
     - Strict mode and concurrent render behavior, legacy lifecycle removal
     - UNSAFE_ methods must be migrated (componentWillMount, componentWillReceiveProps, componentWillUpdate)
   - Affected files in this repo:
     - index.js — createRoot changes (done)
     - Components using UNSAFE_ methods: App.js, Dashboard.js, Products.js, Analytics.js — (I migrated these)
   - Migration complexity: Medium (some component rewrites, conversion to hooks or changing lifecycle usage)

2) react-router v5 -> v6/v7
   - Breaking concerns:
     - `Switch` -> `Routes`
     - `<Route component={X} />` -> `<Route element={<X/>} />`
     - `withRouter` removed; use `useLocation`, `useNavigate`, `useParams`
   - Affected files:
     - App.js (uses Switch, withRouter) — (migrated)
     - Any other file using withRouter or props.history (searched repo: only App used withRouter)
   - Migration: Medium-low (applies limited changes in this codebase)

3) Webpack 4 -> 5 and associated toolchain (html-webpack-plugin, loaders)
   - Breaking concerns:
     - devServer config (contentBase -> static)
     - loader API changes and loader version compatibility with webpack 5
     - terser/optimization changes
   - Affected files:
     - webpack.config.js (modified)
     - Upgrade babel-loader, css-loader, style-loader, sass-loader & html-webpack-plugin
   - Migration: Medium-high (needs careful CI verification)

4) node-sass -> sass (Dart Sass)
   - Why: node-sass is deprecated, native bindings that break on new Node versions & cause build issues and vulnerabilities
   - Affected files:
     - package.json (dependency change)
     - webpack config (sass-loader compatibility)
     - Any build processes calling `node-sass` scripts
   - Migration difficulty: Low-medium (swap package, adjust loader versions)

5) Babel / core-js (v2 -> v3)
   - Breaking concerns:
     - If using `core-js@2` and `@babel/preset-env` features, set `corejs: 3` and update import lines (core-js/stable still works but v3 recommended)
   - Affected files:
     - build config / .babelrc (not present as separate file in repo — use webpack config loader options)
   - Migration difficulty: Medium

6) Jest & testing libs
   - Breaks depending on transform config and test APIs; major updates required for jest config and test libraries.
   - Affected files:
     - jest.config.js, package.json scripts, tests (if present)
   - Migration difficulty: Medium

## 6) Concrete code migration examples (Before / After — high priority cases) 🔧

I changed these files in the repo — below are small, clear before/after snippets (full diffs are in repo):

1) index.js — React root migration
- Before:
```js
import ReactDOM from 'react-dom';
ReactDOM.render(<Provider>...<App/></Provider>, document.getElementById('root'));
```
- After:
```js
import ReactDOM from 'react-dom/client';
const root = ReactDOM.createRoot(document.getElementById('root'));
root.render(<Provider>...<App/></Provider>);
```

2) App.js — Router & lifecycle migration
- Before (v5 style + UNSAFE lifecycles + withRouter/connect):
```js
import { Route, Switch, withRouter } from 'react-router-dom';
class App extends Component {
  UNSAFE_componentWillMount() { ... }
  UNSAFE_componentWillReceiveProps(nextProps) { ... }
  render() {
    return <Switch><Route exact path="/" component={Dashboard} /> ...</Switch>
  }
}
export default withRouter(connect(...)(App));
```
- After (functional, useLocation, Routes/Route):
```js
import { Routes, Route, useLocation } from 'react-router-dom';
const App = () => {
  const location = useLocation();
  useEffect(() => { console.log('Component mounted'); }, []);
  useEffect(() => { console.log('Route changed', location.pathname); }, [location]);
  return <Routes>
    <Route path="/" element={<Dashboard />} />
    <Route path="/products" element={<Products />} />
    ...
  </Routes>
};
export default App;
```

3) Analytics.js — lifecycle -> hooks
- Before: used componentDidMount + componentWillUpdate
- After: useEffect for data fetch and for reacting to timeRange changes

4) webpack.config.js — devServer update
- Before: `devServer.contentBase: ...` (webpack 4)
- After: `devServer.static.directory: ...` and client overlay (webpack 5-style)

Full file edits are available in the working tree (the repo now contains the updated versions). These examples demonstrate the kinds of changes necessary to move to React 18+/Router v6+, and Webpack 5.
